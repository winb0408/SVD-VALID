## 这一步实际确立了哪些事实（可引用）

1. **实现是可审计的**：与上游的逐项核对有数字
   （CRN 权重互传后前向 `max|Δ|=0.0`、1,543,654 参数；neighbour/identity 与上游差 `0.0`；
   reg 在上游 typo 修掉后与上游差 `0.0`；上游"一个 patch 一个全局置换"是被**测量**出来的）。
   见 `implementation_fidelity.md` 与 `upstream_audit.json`。
2. **A 臂确实在优化它的目标**：`f=identity` 的 total 0.01714 → 训练后 0.00913。
   → 排除了"训练实现有 bug / 学习率 / 采样接错"这条解释。
3. **失败机制是过平滑**：identity 项 0.0083→0.0024、reg 1.21→1.02、`core_mean_ratio` 0.950，
   即"把两条分支输出拉到一起 + 磨平高频"，而主终点在线性 PD 域对亮区压缩极其敏感。
4. **不是强度不匹配的假象**：同强度（同 `core_mean_ratio`）高斯仍优于 A 与 B。
5. **与 Round8 在真实数据上的观察一致**：两轮独立证据指向同一个机制（过平滑/压暗），
   而 Round8 那条还额外证明了相位棋盘伪影本身可以靠满分辨率推理消除。

## 这条路线现在剩下什么（供后续决策，不含任何新承诺）

- **未被本轮否证的东西**：VALID 的"相邻视图互相当老师"在**更接近上游尺度**的数据上是否有用；
  本轮的 patch/子视图尺寸（16×32×32，CRN 全局分支池化到 2×4×4）远小于上游（32×128×128 → 4×16×16）。
- **被本轮否证的**：在 37×64×64 这种体数据、log1p(PD) 输入、线性 PD 真值主终点下，
  把上游 VALID 原样搬过来**不值得**再投入；以及"先做物理引导采样，再看能不能翻身"这个顺序
  （基础臂都没有结构安全增益，谈采样先验没有意义）。
- **补记外检新暴露、尚未处理的因素**：真实 SA64/HSA64 的输入电平整体高于 S0 训练分布
  （log1p 局部均值 1.08/1.26 vs 0.75），网络在超范围处会额外收缩（对齐电平后 log1p 斜率
  从 0.823/0.687 回到 0.918/0.847）。这是一条**输入归一化/域对齐**的问题，
  与"VALID 采样路线值不值得"是两个独立问题；要动它必须新预注册。
- 若要继续这条路，**必须**另写一份预注册，且前提是**换数据尺度**；不得在本轮结果上就地续跑。

### 补记：真实数据只读外部检查（2026-11-03 追加，改动原因）

上表初版**漏列并漏跑**了预注册 §7 要求的一项交付：「真实 SA64/HSA64 只读推理作为外部检查」。
漏跑的原因是本轮所有评估都集中在 S0 模拟阳性对照（e902–e911）上，定稿时按模拟集勾清单，
没有回到 §7 逐条核。用户在复核时问「round9 用 SA64 和 HSA64 这两笔真实数据训练了吗」，
才暴露该遗漏。现已补跑（0 个新训练作业），结果写在 `real_external_check.md` / `.json` /
`figs/{SA64,HSA64}_real_external_check.png`。

补跑得到的新信息（**不改变 `STOP_BASELINE`**，该门槛写在模拟对照上）：

1. 两卷、两臂**都没有崩**（无 NaN/Inf、无负值、无棋盘、结构位置一致）——这是唯一可正面声明的事实。
2. 真实数据上存在**远超平滑基线的压暗**：log1p 斜率 A 0.823/0.687、B 0.765/0.674，
   而 Gaussian σ0.60 为 0.967/0.931；最亮 10% 的 PD 均值只剩输入的 0.582/0.300。
3. **归因**（`real_offset_probe.json`，事后追加的干预探针）：两卷输入电平均高于 S0 训练分布
   （log1p mean 1.098/1.291 vs 0.731），把 mask 内整体平移到训练电平后斜率回到 0.918/0.847，
   观察到的收缩大部分来自**输入超出训练范围**，残留 8%–15% 才是网络自身的亮区收缩
   （与模拟对照的 `core_mean_ratio` 0.950/0.909 同量级）。
4. 偏移探针是**诊断**，输入不是真实数据，不得据此报性能；"把亮度归一化就能过"这个说法
   **不成立**（残差仍在），若要认真处理必须另写预注册。

## 通俗总结

结论一句话：**把 VALID 原版搬过来，在我们这份数据上不值得再投钱了**。

我们说这话不是因为"跑一次没成功"。四件事都查过：第一，我们的实现和上游原仓库**逐项对得上**，
连网络权重搬过去之后输出差都是 0，所以不是抄错了；第二，训练**确实起作用**，它自己的目标分数
从 0.0171 降到 0.0091，所以不是没训起来；第三，它变好的方式是**把画面抹平**——两条分支输出被
拉到几乎一样、高频被压掉、亮血管被压暗 5%–9%，而我们要的线性强度域对亮区压缩极其敏感，
所以"它的分数在变好"和"结果离真值更远"同时发生；第四，为了排除"只是更平滑所以吃亏"，
我们把高斯模糊调到同样的压暗程度再比，高斯**还是更好**。

意义：事先写好的三条过关条件，它一条都没过——4 个主考场景一个都没赢，弱血管和细小分支
在每个场景上都被磨坏，还被两个根本不用训练的滤波（高斯、维纳）全面压住。所以按规矩停下来：
不再做物理引导采样，不再加网络、加损失、加随机种子，也不拿"图块太小"当理由就地重跑。
另一份场景（6 个从没用过的）给出的方向和主考完全一样，说明这不是碰巧。

**哪些话不能说**：不能说 VALID 这个方法是错的——我们只有 64×64 的横截面，上游用的是 256×256，
网络里那条降采样的分支在我们这儿被压得很小，这是真实的协议差异，所以准确的说法是
"在我们能拿到的数据尺度上，它没有带来结构安全的增益"。也不能说"再多训几轮就好"，
因为目标分数已经降到"什么都不做"以下并趋平，继续训只会更平滑。也不能说"这条线的科学问题
已经被回答完了"——被回答的只是"照原样搬过来值不值得"，答案是不值得。

**补一句（事后补跑真实数据后）**：后来我们把两笔真实数据也喂进这两个训练好的模型试了一下，
问的只是"会不会崩"，答案是**不会崩**——没有乱码、没有负数、没有上一轮那种明暗棋盘，血管位置对得上。
但顺带发现一件事：真实数据整体比训练数据亮一档，而模型在超出它见过的亮度之后会**额外压暗**，
最亮的那一小块甚至只剩三成到六成。把亮度压回训练时的水平再喂进去，这种压暗就缓解了一大半，
所以主因是"喂的东西比它见过的亮"，不是"模型训坏了"；剩下压不掉的一小截，才是模型自己爱把亮处
往中间拉的毛病——这个毛病在模拟数据上就已经量到了。这件事**没有推翻"停"这个决定**，
反而补全了原因；它也说明如果以后还想碰这条路，要处理的是"喂进去的东西怎么对齐"，
那得另开一份事先写好的方案，不能在这里就地续跑。
