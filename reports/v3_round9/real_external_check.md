## 2. 输入域换算（这一处写错，整份检查作废）

真实体存的**不是** log1p，而是用 B1 冻结统计量标准化后的 logeps：

```
z = (logeps_raw − mean) / std,   mean = -0.0950694532424626, std = 0.882857398573932
logeps_raw = log(PD/s + 1e-3)
```

（见 `scripts/v3_round7_ours_prep.py`、`reports/v3_round4/b1_norm.json`。）

而 Round9 的训练/测试数据是 `x_log = log1p(PD/s)`。**两者不是仿射关系**，所以
「直接反标准化」只能拿回 logeps，不能拿回 log1p。正确链条：

```python
logeps = x_std * std + mean
u      = max(exp(logeps) - 1e-3, 0)     # u = PD/s
x_log  = log1p(u)
# 往返断言（脚本内 assert）：
assert np.allclose(np.log(u + 1e-3), logeps, atol=1e-6, "logeps→log1p 往返不自洽"
```

与 S0 训练约定一致：`x_log` 在 mask 外置 0。脚本
`scripts/v3_round9_real_external_check.py` 里这段链条和断言都写在同一处，起始版本的
"仿射反标准化"写法已删除并在文件头记明原因。

输出转换：`pd = s * expm1(y)`；显示 `db = 10log10(max(pd,1e-12)/refmax)`，
`refmax` 由**输入** PD 在 mask 内的最大值定，**所有方法共用同一个 refmax**，色标固定 `[-25, 0]` dB，
不逐图自动拉伸，ROI 固定为 `valid_mask`（两卷均为 120,232 voxel，36×64×64，去掉 1 层奇数维以对齐）。

## 6. 归因：是网络学到了"压暗"，还是输入电平超出训练范围？

两个真实卷的输入统计与 S0 训练分布比：

| | log1p mean | log1p std | log1p max | 局部均值（5³ 窗） | 局部对比 |
|---|---|---|---|---|---|
| S0 训练（12 场景） | 0.7314 | 0.3778 | 2.117 | 0.697–0.750 | 0.031–0.041 |
| SA64 | 1.0981 | 0.2042 | 2.6625 | 1.080 | 0.0575 |
| HSA64 | 1.2908 | 0.5734 | 5.3772 | 1.255 | 0.1436 |

**两卷的输入电平都在训练分布之上**（+0.37 / +0.56 in log1p），HSA64 的极大值甚至是训练
最大值（2.117）的 2.5 倍。这提示压暗可能来自"超范围收缩"而非"学到的映射"。

为此做了一次**干预探针**（`scripts/v3_round9_real_offset_probe.py`，
`reports/v3_round9/real_offset_probe.json`）：把整个 mask 内减常数 `c`，使其均值对齐 S0 训练
的 0.7314（mask 外仍为 0，保持训练约定；`c` 不改变斜率），重跑同一 checkpoint。

| | 原始斜率 | 偏移后斜率 | 原始 core ratio(log1p) | 偏移后 core ratio(log1p) |
|---|---|---|---|---|
| SA64（c = 0.3667） | 0.823 | **0.918** | 0.740 | **0.987** |
| HSA64（c = 0.5594） | 0.687 | **0.847** | 0.646 | **0.901** |

（core ratio 均为 log1p 域、输入最亮 10% voxel 上的「输出均值 / 对应输入均值」；原始一列取自
`data/processed/v3_round9_real/{seq}/A_log1p.npy` 与原始输入直接相比，偏移一列取自探针输出与
平移后的输入相比。Gaussian σ0.60 的同一量为 0.978/0.957，可见原始压暗与平滑基线差得很远。）

**归因结论**：电平偏移解释了大部分收缩（core ratio 从 0.740 → 0.987、0.646 → 0.901），
但**没有全部解释**——对齐电平后仍留 8–15% 的收缩，与模拟阳性对照里观察到的 5–9% 压暗同量级。

**探针本身的不完美（必须同读）**：整卷平移只能对齐均值，对齐不了形状。SA64 平移后 mask 内最小
0.122（S0 最小为 0，可接受）；HSA64 平移后有 voxel 落到 **−0.136**，即落到了训练域之外的下侧
（S0 里不存在负值）。因此 HSA64 那一栏"残留 15%"里有多少来自这个负值尾部、有多少来自网络自身的
亮区收缩，本探针**分不开**。另外 HSA64 的输入 std（0.573）仍远大于 S0（0.378），平移不改 std。
也就是说：

1. 主要机制是 **输入电平超出训练范围 → 网络收缩**（OOD），这一条是本轮没在设计里考虑到的；
2. 次要机制是 **网络本身在压亮区**（模拟对照已测到 `core_mean_ratio` 0.950/0.909），
   与 `STOP_BASELINE` 诊断的"过平滑 + 线性 PD 端点对亮区压缩极敏感"一致。

偏移探针的输入**不是真实数据**，必须只当诊断看，不得据此报任何性能。

## 8. 这份检查确立了什么、不能说什么

**确立（可引用）**
1. Round9 的两个 checkpoint 喂真实 SA64/HSA64 **不会崩**：无 NaN/Inf、无负值、无棋盘、结构位置一致。
2. 真实数据上存在**系统性压暗**：log1p 斜率 0.69–0.82（平滑基线 0.93–0.97），
   最亮 10% 的 PD 均值只剩输入的 0.58/0.30（Gaussian 0.95/0.84）。
3. 压暗的**主要来源是输入电平超出 S0 训练范围**（对齐电平后斜率回到 0.85–0.92）；
   次要来源是网络自身的亮区收缩，与 Round9 模拟对照的诊断一致。
   该归因**是部分的**：探针只平移均值，未对齐分布形状，HSA64 平移后仍有负值尾部与偏大的 std。
4. 因此 Round9 的结论**不应**被读成"网络被训坏了"——更准确的是
   "在训练分布内它就偏平滑，出了训练分布它还会额外压暗"。

**不能说（明确禁止）**
- 不能说去噪**有效**或**更好**：真实数据没有干净真值，本文档不含任何效果主张。
- 不能用这两卷与高斯/维纳的差距去**排名方法**：`core ratio` 等只是自比代理，
  没有真值就无法区分"压暗"和"正确抑制背景"。
- 不能据此**修改** `STOP_BASELINE`，也不能把这条 OOD 观察当成"再训一轮就能过"的理由——
  电压偏移是在模拟对照之外新发现的因素，要处理它必须**新写预注册**（含新的输入归一化协议），
  不能在本轮结果上就地续跑。
- 不能说"电平归一化后就好了"：探针只做了整体常数平移，残差 8–15% 仍在；
  HSA64 平移后还有负值尾部落回训练域之外，所以连"已经对齐"都不能说。

## 9. 通俗总结

这一步只回答一个问题：**把 Round9 训出来的东西直接喂给两笔真实数据，会不会崩？**

先纠正一件事：Round9 的文件里没有这两笔真实数据的结果，是因为**这一项漏跑了**，不是跑过但没放图。
预注册里写了要做，定稿清单里漏了，这次补上。补上不改变任何结论——Round9 判"停"的门槛是在
模拟数据上事先定好的，跟这一步无关。

结果分三层。第一层是好消息：**没有崩**。两卷、两个权重都没有出现乱码、发散、负数、
上一轮那种明暗棋盘，血管位置和输入对得上。第二层是问题：**整体被压暗了**，而且压得不轻。
我们用一个简单的量来量它——"输出大致等于输入的多少倍"。两个不用训练的手机滤镜式处理
（高斯模糊、维纳滤波）这个数是 0.93–0.97，也就是基本只把画面抹平一点；这两个网络是 0.69–0.82，
最亮的那 10% 区域甚至只剩 0.58（SA64）和 0.30（HSA64）。换句话说，**最该保留的亮信号被砍掉最多**。

第三层是"为什么会这样"，这是这次额外查出来的、之前没想到的：**真实数据的整体亮度比训练数据高了一档**
（对数尺度上高 0.37 和 0.56，HSA64 的最亮值甚至是训练集最亮值的两倍半）。我们做了个对照实验：
把输入整体压回训练时的亮度再喂进去，压暗就缓解了一大半（斜率从 0.82 回到 0.92、0.69 回到 0.85）。
所以主要原因不是"网络被训坏了"，而是**喂给它的东西比它见过的亮**；剩下还有 8%–15% 的压暗
压不掉，那一部分才是网络本身"爱把亮的东西往中间拉"的毛病——这个毛病在模拟数据上就已经量到了
（亮区被压低 5%–9%），只是到了真实数据上被放大得更明显。

**哪些话现在不能说**：不能说它去噪有效——真实的干净图我们没有，这份检查从头到尾没做任何"更好"的主张；
也不能拿它和高斯、维纳比高低，因为没有真值，"压暗"和"正确地把背景压下去"根本分不开；
更不能说"把亮度归一化一下就能过关"——那个对照实验只压了整体亮度，还剩一截压不下去，
而且它是在结果出来之后新加的，按规矩必须另写一份预注册、不能再就地续跑。
最后，这件事**没有推翻** Round9 的"停"这个决定，它只是把原因补全了一层：
在它见过的数据范围内它偏平滑，出了范围它还会额外压暗。
