## 1. B0（无训练）：真实数据三域条件统计

### 1.1 口径（冻结）

- 数据：SA64 / HSA64 原始 `.mat`，全帧 SVD、官方带 `[59,350)`，K=4 个等长连续块（固定基，
  与 R0 同口径）。块的离散度当噪声方差代理；块差分的空间 ACF 当噪声空间相关代理。
- 三域：`linear = PD`、`log1p = log1p(PD/s)`、`logeps = log(PD + 1e-3·s)`；
  `s = median(pd_full[valid])`（SA64 3730，HSA64 583485）。
- 共用协变量 `x = log(pd_full)`，三域**同一组** 8 分位分箱。背景区 = `PD ≤ q20(valid)`。

### 1.2 结果

| 域 | SA64 斜率 | HSA64 斜率 | 乘性噪声正控制（SA64 / HSA64） | Jensen 间隙中位数（SA64） | 奇偶相关（SA64） |
|---|---|---|---|---|---|
| `linear` | +2.147 | +2.141 | +2.097 / +2.063 | 1.0e-4 | 0.755 |
| `log1p(PD/s)` | +1.371 | +1.459 | +1.325 / +1.372 | 5.2e-4 | 0.769 |
| `log(PD+10⁻³s)` | **+0.035** | **+0.107** | +0.017 / +0.007 | 3.5e-3 | 0.791 |

斜率含义：协变量已是对数刻度，`d log Var / d x`；≈2 表示方差 ∝ 信号²（乘性），≈0 表示方差与信号无关。

**噪声空间相关（块差分 ACF，最近邻）**：SA64 z/y/x = −0.006 / 0.425 / 0.169；
HSA64 = 0.050 / 0.505 / 0.235。三域几乎相同（相差 ≤0.02）——
取对数不改变空间相关结构，与 SVD-SN2N 自己的说法一致。

### 1.3 三个层级（任务书 §2 要求分开写）

**已测事实**
1. 线性域方差随信号强烈增长（斜率 ≈2.14，两套数据一致），且与独立乘性噪声正控制（2.06–2.10）吻合。
2. `log1p(PD/s)` **只部分稳定化**（1.37 / 1.46）：它在 `PD ≲ s` 时行为接近线性，所以低亮区方差仍随信号变。
3. `log(PD + 10⁻³s)` **几乎完全稳定化**（0.035 / 0.107），与正控制（0.017 / 0.007）同量级。
4. 取对数引入系统性下沉（Jensen 间隙：linear 1e-4 → logeps 3.5e-3 自然对数单位），
   这是可预测的确定量，反变换时不会自动消失。
5. 奇偶两半的残差相关 0.75–0.86，说明"两块可当独立 N2N 观测"在真实数据上**并不成立**；
   R0 的"非共享参考残差相关 0.017/0.036"只是一个**差分代理**，不能推广成"所有目标噪声都满足 N2N 条件"。

**代理假设（未证明）**
- 块间方差 = 噪声方差：只去掉共享静态/血管信号，残留共用基、时间漂移与 log 非线性；
- 块差分 ACF = 噪声 ACF：同上；
- 真实数据的"信号协变量"用的是同一卷的 `pd_full`（含噪），高信噪处偏差可忽略、低信噪处会稀释斜率。

**训练有效性：NOT_MEASURED_IN_B0**
"方差更平"不等于"网络在 log 域学得更好"；这一点只能由 B1 的三臂短训练回答。

## 2. B1（三臂短训练）

### 2.1 开跑前的一次修订（重要）

原预注册 §3.2 的第三臂写成 `log(PD·ε/s + ε)`，它在代数上等于 `log1p(PD/s) + log ε`，
经训练集仿射标准化后与第二臂**逐位相同**（实测最大偏差 5.7e-7、相关 1−6e-14）。
照原样跑会得到"同一实验跑两遍"的假结果。修订把 ε 移到分母侧：`x = log(PD/s + ε)`，
并保留 `u = PD/s` 作为三域的共同物理尺度。详见修订文档 §1–§3；修订在**任何训练启动之前**完成。

### 2.2 配置（三臂只差表示域）

| 项 | 值 |
|---|---|
| 档位 / 数据 | `low`，训练 12 卷（s200–s211），选参 e900/e901，报 e902–e905 |
| 网络 | `--mode dense --arch-head residual --zero-init-final`，`features 16`，`groups 4`，`patch 32×64×64` |
| 优化 | `lr 1e-4 poly`，`seed 3407`，`pairing within`，15 epoch × 500 step |
| 归一 | 每域训练集仿射标准化（常数见 `b1_norm.json`），不在留出集重算 |
| 目标 | 同一变换作用于 `gt_imaging_pd`（PSF 匹配的成像真值） |
| 评价 | 反变换回线性 PD → 回到冻结 log1p 指标域 → 与 `gauss(0.6)` 对照 |
| 作业/预算 | 3 个作业，≈0.63 GPU·h（Round4 累计 ≈0.78/8，作业 3/8） |

规则（预注册 §3.3，**未事后修改**）：相对 `log1p` 臂 `rmse_img` 改善 ≥3/4 体，
且不劣于 `gauss(σ*)` 4/4 体，且 `recall_at_fpr5` 不比高斯差 >0.02（4/4 体）。

| 臂 | 优于 log1p | 不劣于 gauss | `ret_p10` 达标 | 机械判定 |
|---|---|---|---|---|
| `linear` | 3/4 | 4/4 | 4/4 | clear_positive_signal |
| `log1p` | 4/4（**自比，恒真**） | 4/4 | 4/4 | clear_positive_signal |
| `logeps` | 4/4 | 4/4 | 4/4 | clear_positive_signal |

**但必须写清两条会削弱这个门的东西，否则会读数过头：**

1. **第 1 条判据对 `log1p` 臂是同义反复**：`log1p` 就是"现正控制"，拿它跟自己比必然 4/4。
   这是预注册文本的漏洞（写"相对 log1p 改善"时没排除 log1p 自己）。
   本轮**不追溯修改判据**，但结论里只用 `logeps` / `linear` 这两条真正跨臂的比较。
2. **第 3 条判据在形式上已失效**：它依赖 `METRIC_RESOLVED`，而 P0 已判定结构尺子的 0-Gate 无区分力
   （`baseline_pareto.md` §3），预注册 §2.3 写明"结构指标失效 ⇒ B pilot 的结构增益判据同步失效"。
   本轮照样把这三项算了出来（都通过），但它**不能**被当作"结构安全"的证据。

### 2.6 机制核对（预注册 §3.3 对 `logeps` 的附加要求）

预注册要求："只有 `logeps` 满足 → 必须先证明收益来自条件方差/偏置改善（B0 的对应量），
再谈 C；**不得**归因 I1"。核对结果：

| 表示域 | B0 方差稳定化斜率（SA64 / HSA64） | B1 `var_bg` | B1 `rmse_img` |
|---|---|---|---|
| `linear` | +2.147 / +2.141 | 7.27e-05 | 0.0085 |
| `log1p` | +1.371 / +1.459 | 7.73e-05 | 0.0088 |
| `logeps` | +0.035 / +0.107 | **6.57e-05** | **0.0081** |

- **支持的一半**：稳定化最彻底的 `logeps` 同时拿到最低 `var_bg` 与最低 `rmse`，
  且它的优势集中在方差项（`bias_ves` 与 `linear` 同量级）——与"方差稳定化 → 背景噪声压得更低"一致。
- **不支持的一半**：如果机制只是方差稳定化，`linear`（斜率 2.14）应当明显差于 `log1p`（斜率 1.4），
  但实测 `linear` 反而略优于 `log1p`（3/4 体）。所以斜率**不是**唯一因素，
  也不该把 `logeps` 的优势说成"因为方差稳定化"——只能说**与之一致**，不构成因果。
- 另一条公平性保留（预注册 §3.2 已预置）：标准化只对齐一阶/二阶矩，
  **不能保证三域的"可优化性"相同**；15 epoch 下 `logeps` 的 loss 尺度也不同（1.94e-4 最大），
  因此"收敛更快"与"表示更好"在这轮里仍然混在一起。

### 2.7 追加训练（预注册允许的唯一一条）

预注册 §3.3 允许"最优臂从 15 epoch 续训到 40 epoch，同一 checkpoint，不换种子"。
最优臂 = `logeps`（4/4 体胜出）。执行记录：

- `train.py` 原本**没有**续训入口，本轮新加 `--resume`（只加载 `model` 权重，不恢复优化器状态；
  `poly` 学习率按**全局** epoch 继续衰减），并用 2 卷 × 20 step 的烟测核对了"权重确实加载"
  （首步 loss 1.83e-4，与 15 epoch 末的 1.94e-4 同量级）。
- 续训作业：`--epochs 40 --resume runs/v3_round4/b1_logeps_s3407/latest.pt`，
  输出 `runs/v3_round4/b1_logeps_s3407_40ep`，01:04 启动，25 epoch ≈ 0.65 GPU·h（job 4/8）。
- 评估：`scripts/v3_round4_b1_eval.py --arms logeps --arm-suffix _40ep --out-json
  reports/v3_round4/b1_pilot_40ep.json`。

**读法（不做事后解释性豁免）**

1. **预注册允许的那条追加训练没有带来提升，反而在 4/4 体上一致变差**（幅度 4.3–4.8%，很小但方向一致）。
   三臂排序的结论不变：40 ep 的 `logeps` 仍是 0.00848，仍优于 `gauss(σ*)` 的 0.00995
   （逐场景 +6.8% / +7.4% / +27.0% / +17.3%，4/4），也仍优于 15 ep 的 `linear`(0.0085)。
2. 变差集中在 `var_bg`（+9.1%）与 `bias_ves`（负偏从 −0.00144 到 −0.00191，幅度加大 33%）：训练更久 ⇒ 输出更"平滑"、噪声压得更狠，
   但血管幅度被连带压掉。与"12 卷训练集 + 12 万步"的过拟合方向一致，**但本轮没有做 early-stop 扫描，
   所以"过拟合"只是与证据一致的假设，不是被证明的原因**。
3. **这不改变 §2.5 的 Gate 判定**（Gate 在 15 ep 上原样执行过，不回填、不重跑、不修改），
   但它把"再多训一会儿会更好"这句话**从可选解释里删掉了**：本轮唯一一次"加预算"的尝试是负结果。
4. 因此 `DECISION.md` §7 的确认轮设计里，"40 epoch"这一档应当**改成"≤20 epoch + 在 e900/e901 上做
   early-stop 选点"**，才算吸收了这条负结果；这条改动属新预注册，需用户批准后才能跑。

## 3. 通俗总结

这一步问的是一个很具体的问题：**把超声功率多普勒的图像先"压一压"（取对数），再去训练网络，会不会更容易、
更安全？**"压一压"是我们想验证的核心做法之一，文献里的同类工作也把它当成关键步骤。

先看事实层面。我们手上没有真值那批数据（原始的多普勒容积），所以先用统计量看三种"压法"下的噪声行为：
原始尺度（linear）、常用的一种压缩（log1p）、以及压缩得更狠的一种（logeps）。结论很干脆：
原始尺度下，信号越亮噪声涨得越快（斜率约 2.1，几乎跟信号平方同步）；常用压缩只压下去一半（约 1.4）；
压缩得更狠的那种基本把噪声"拍平"了（约 0.04–0.1）。用一个模拟的"乘性噪声"正控制去核，方向完全一致——
说明这不是算错了，而是这三组量本来就该这样。

然后是训练。三组网络除了"喂进去的数值怎么压"以外，配置逐项相同，各自训 15 个 epoch，
在四个**没见过**的场景上打分。结果：三组都明显好过传统的高斯平滑（误差低 4%–44%，
血管位置被"磨细"的系统偏差只有高斯平滑的四分之一左右）；而在三组之间，
压得最狠的那组（logeps）在四个场景里**全部**最优，误差比常用压缩那组低 6%–9%。
也就是说：**"把信号压平"确实有用，而且越平越好**——这跟第一步的统计结论方向一致。

但有两句话现在**不能**说。第一，不能说"这就证明了我们的方法有效"：15 个 epoch、单一随机种子、
只有四个场景，这是探索级证据，不是可发表的验证；而且三组的差距集中在"背景噪声压得更狠"这一项，
不是"血管保得更好"。第二，不能说"增益来自对数表示"——因为训练损失、优化难度也同时变了，
这轮没法把"表示更好"和"更好训"分开。更准确的说法是：**表示域的选择确实有可测的影响，
方向与"方差稳定化"一致，但机制尚未被单独证明。**

还有一点值得记住：这一轮之前，我们一直以为问题出在"采样方式不够正交"；现在证据指向另一个地方——
**上游那个"取对数压缩"才是真正起作用的那一步**，而采样方式的毛病（两半图像错位半个体素）
是另一件事，需要靠重新设计采样解决，不能靠"更聪明的先验"补救。
