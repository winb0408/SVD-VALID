## 1. 一句话结论

**匹配空间算子后，SA64 的交叉拟合臂对确实比 Tetris 对照低 16%–19%，方向与门槛一致；
但这条边距并不是交叉拟合设计带来的——把同一批帧随机切成两半，能得到同样大甚至更大的边距。
所以现在这个残差 proxy 测的是"两条臂来自不同帧"，而不是"噪声是否独立"。**

按审计 §7 的三选一：**第 2 项（匹配后结论不确定，不训练，先修指标可解释性）**。

## 2. 审计意见的核对：哪些成立，哪些归因错了

### 2.1 成立的（4 条，全部复现）

| 审计主张 | 复现结果 | 证据 |
|---|---|---|
| 空间算子是混淆项，且是决定性的 | **成立。** HSA64 匹配后 +0.61/+0.51 变成 −0.012/−0.022；SA64 从 +0.69/+0.58 变成 −0.259/−0.304 | `matched_ci.json` |
| `1/sqrt(N)` 用错了，两臂应是 `σ√(2/N)` | **成立。** σ√(2/133)=0.0368，实测 0.0369；σ/√133=0.0260 对不上 | 见 §5 |
| "干净 8 折"措辞错误 | **成立，且比审计说的更糟。** `f0∉A∪B` 的 8 折和 `f0∈C` 的 8 折是**同一批折**——frame 0 每次都落在 C 里，而 C 就是投影算子的来源 | `frame0_sensitivity.json` |
| 跨秩规则拼接数字（"+0.66 升到 +0.75"） | **成立。** 已改成逐规则并列 | `reports/phase2_pair_statistics.md` |

### 2.2 归因错误的（1 条，量级差一个数量级）

审计 §1.2 把混淆归给"块平均 / 回填改变了高频内容"，也就是 **smoothing**。
实测分解（`variants.json`，块均值 r，绝对量；两列是**顺序增量**：
先 as_impl → v2（只加 smoothing），再 v2 → v1（在 smoothing 之上加相位切分））：

| 序列 | 规则 | as_impl | v2 只加 smoothing | Δsmoothing | v1 smoothing+相位切分 | Δ相位切分 |
|---|---|---|---|---|---|---|
| SA64 | `proportional` | 0.5814 | 0.5930 | **+0.0116** | 0.2596 | **−0.3334** |
| SA64 | `clutter_knee` | 0.5233 | 0.5377 | **+0.0144** | 0.2344 | **−0.3033** |
| HSA64 | `proportional` | 0.9722 | 0.9777 | **+0.0055** | 0.5978 | **−0.3799** |
| HSA64 | `clutter_knee` | 0.9516 | 0.9634 | **+0.0118** | 0.6180 | **−0.3454** |

**Smoothing 只贡献 +0.0055…+0.0144；相位切分贡献 −0.303…−0.380——差 20–60 倍。**
审计把矛头指向了小一个数量级的那一项。正确的说法是：
**混淆来自 Tetris 把"同一帧的同一个噪声实现"按相位劈给两条臂，而交叉拟合的两条臂来自不同帧。**
这不是"处理方式不同"，是"信息的来源不同"——所以它不能被"匹配一下算子"消除，
只能被"给对照组一个同样来自不同帧的臂"消除。这正是 §4 的随机划分零分布要做的事。

### 2.3 审计没发现、但更大的（3 条）

**(a) 原报告 §4.1 的表格混用了两个估计量。** 电平列用的是"折内中位数再跨折取均值"，
相对降低列用的是"折内均值算比值再跨折取均值"。两者不是同一个量，
用表里的电平手算相对降低会差 0.10–0.30。已在报告里显式写明。

**(b) frame 0 不是"轻微偏离"，它在自己的臂里是主导项。**
在 `sa64_int5_c1_2_4a0b3`（frame 0 在 A）里：

| 量 | 值 |
|---|---|
| frame 0 的 `‖P x_t‖²` | 2.59e9 |
| A\{0} 的逐帧中位数 | 8.98e6 |
| 比值 | **288 倍中位数** |
| 占 D_A 分子的份额 | **76.6%** |
| 在 400 帧中的排名 | **第 1** |
| 它的 Gram 总能量 | 1.145× 中位数（正常） |
| 它在官方带里的能量 | 0.0015× 中位数（**几乎为零**） |

最后两行是关键：它在总能量检查里看不见，却支配着管线真正用的那个带。
**所以"总能量正常"不能证明"这一帧无害"。**

**(c) frame 0 是在"帮"交叉拟合过关，不是在害它。**
把 frame 0 从管线里真正移除后（`frame0_exclusion.json`，`variant_a`/`variant_b`）：

| 序列 | 规则 | as_impl | 移除 frame 0 | 通过的折数 |
|---|---|---|---|---|
| SA64 | `proportional` | +0.691（3/16 折为负） | **+0.949（0/16 折为负）** | 3/16 → **0/16** |
| SA64 | `clutter_knee` | +0.578（3/16 折为负） | **+0.879（0/16 折为负）** | 3/16 → **0/16** |
| HSA64 | `proportional` | +0.606 | +0.607 | 0/3 → 0/3 |

HSA64 上"移除 frame 0"是**空操作**（+0.606 → +0.607），因为它没有异常帧——
这反过来验证了移除方法本身没有引入偏差。
SA64 上那 3 个原本通过 −10% 门槛的折，正是 frame 0 落在 A 里的折；
移除后从 −0.173/−0.282/−0.235 翻成 **+0.789/+0.751/+0.761**。

## 3. 核心新证据：随机划分零分布

### 3.1 为什么要做

§2.2 的分解说明，混淆的根源是"两条臂是否来自不同帧"。那么"匹配算子后 SA64 通过 −10% 门槛"
这件事，就必须回答一个归因问题：

> 这条边距，是 **C/A/B 交叉拟合设计**带来的，还是**任何把同样的帧切成两半的做法**都会带来？

如果随机切也能得到同样的边距，那么门槛测的就不是"噪声独立性"，
而是"两条臂来自不同帧"——后者对**任何**划分都成立，因此不含信息。

### 3.2 怎么做

每一折里，把 A∪B 的帧池随机重排、按下标切成同样大小的两半 R1/R2（不重叠、不换回），
用**同一折的同一个投影算子**投影，再走**同一个匹配算子**、和**同一个 Tetris 对照**比较。
每折重复 40 次。C 不动、秩带不动、Tetris 对照不动，唯一变的是"哪几帧进哪条臂"。

### 3.3 结果

| 序列 | 规则 | 交叉拟合边距 | 随机划分边距（均值） | 随机划分 p95 | 交叉拟合在零分布中的百分位 |
|---|---|---|---|---|---|
| SA64 | `proportional` | −0.259 | −0.230 | −0.198 | **64** |
| SA64 | `clutter_knee` | −0.304 | −0.266 | −0.237 | **60** |
| HSA64 | `proportional` | −0.012 | −0.033 | −0.024 | 100 |
| HSA64 | `clutter_knee` | −0.022 | −0.057 | −0.049 | 100 |

**SA64：交叉拟合落在随机零分布的第 60–64 百分位——比一半以上的随机划分还差。**
16 折里只有 3 折（全部来自 `cont3` 家族）低于随机零分布的 p05。

拆到划分家族看，结论更清楚：

| 家族 | 帧的排列方式 | CF 边距 | 随机边距 | CF 百分位 |
|---|---|---|---|---|
| `cont3` | 连续三段 | −0.308/−0.326 | **−0.009/−0.008** | **0** |
| `int3` | 交错三组 | −0.206/−0.256 | −0.226/−0.279 | 65/69 |
| `int5` | 交错五组 | −0.261/−0.313 | −0.297/−0.339 | 82/76 |

`cont3` 是唯一 CF 明显优于随机的家族，原因可解释：
连续分段的随机重排会把**时间上相邻的帧**打散到两条臂里，而相邻帧高度相关，所以随机划分反而更差。
**这不是交叉拟合的功劳，是"连续切块保住了时间结构"的功劳。**
交错家族（`int3`/`int5`，共 13 折）里，随机划分与 CF 边距相当甚至更好。

### 3.4 这条证据意味着什么

它把门槛的解释权拿走了：
**一条 −0.16…−0.19 的边距，在"随机切帧"这个零假设下同样能拿到，**
所以它不能用来判定"交叉拟合产生了独立的噪声监督信号"。
配套的 HSA64 行（百分位 100，即 CF 比所有随机划分都差）说明这不是 SA64 特有的现象。

## 4. 匹配算子 × frame 0 的 2×2

只看"匹配后"或只看"移除 frame 0"都会得出片面结论，必须一起看
（`frame0_matched.json` / `matched_ci.json`）：

| 序列 | 规则 | 未匹配 as_impl | 匹配 as_impl | 匹配 + frame 0 移除 | CI 排除 0 的折数 |
|---|---|---|---|---|---|
| SA64 | `proportional` | +0.691 | −0.259 | **−0.163** | 16/16 |
| SA64 | `clutter_knee` | +0.578 | −0.304 | **−0.194** | 16/16 |
| HSA64 | `proportional` | +0.606 | −0.012 | −0.012 | 3/3 |
| HSA64 | `clutter_knee` | +0.506 | −0.022 | −0.021 | 3/3 |

三件事同时成立：

1. **匹配让符号翻正**（+0.69 → −0.26），审计的定性判断对。
2. **frame 0 贡献其中约 1/3**（−0.259 → −0.163），移除后仍在 −10% 门槛内，但余量从 2.6× 掉到 1.6×。
3. **匹配后边距按 frame 0 角色分层仍然分得开**：
   as_impl 下 f0∈A 是 −0.411（n=6）、f0∈B 是 −0.357（n=2）、f0∈C 是 −0.121（n=8）；
   移除 frame 0 后三层收敛到 −0.174/−0.250/−0.133——**说明这个分层就是 frame 0 造成的，不是设计差异。**

复算一致性：从 IQ + Gram 直接重建的两臂与 Phase 1 落盘的 `.npy` **最大相对差 8.4e-4**
（SA64）/ 7.2e-4（HSA64），差异来自 float32 与 complex64 的舍入，不是约定错误。

## 5. `1/sqrt(N)` 的修正

两臂各自是 N 帧的平均，各自的噪声是 σ/√N，**两条臂的噪声独立**，所以
`rms(a/b − 1)` 的期望是 `√(σ²/N + σ²/N) = σ√(2/N)`，不是 `σ/√N`。

- N = 133：`√(2/133) = 12.3%`，`1/√133 = 8.7%`
- 实测 SA64 `rms_rel_diff` = 12.3%（口径：mid ROI，P1 臂对）
- 反解 σ：σ = 0.0369/√(2/133) ≈ 0.294

原报告 3 处 `1/√133 = 8.7%` 已全部改成 `√(2/133) = 12.3%`。
**注意**：这只修正了机制说明，不改变门槛判定——它解释的是"两臂为什么差这么多"，不是"两臂该不该独立"。

## 7. Gate D 裁决

### 7.1 三选一的判定

| 选项 | 判定 | 理由 |
|---|---|---|
| 1. 实现修正后仍失败 | **不选** | 未匹配的 +0.69 确实是混淆造成的；说"改完还是失败"会重复审计已经推翻的那个归因 |
| **2. 匹配后结论不确定** | **选** | 匹配后 SA64 虽进 −10% 门槛（−0.163/−0.194），但随机划分零分布显示同等边距可由任意切帧获得（第 60–64 百分位），proxy 无法区分"设计有效"与"臂来自不同帧" |
| 3. 匹配后达到既定门槛 | **不选** | 审计 §7 明确要求"经空间 bootstrap、帧预算和 frame0 敏感性检查保持稳定"才允许提训练申请；三项确实稳定，但**构念效度检查（随机划分零分布）不通过**，不满足"达到门槛"的实质含义 |

**裁决：第 2 项。当前残差 proxy 不能判定噪声独立性；先解决指标可解释性，不训练。**

### 7.2 门控状态

- **Phase 3 训练：不开。** 依据审计 §0.1、§8，以及本裁决。
- **不追溯修改预注册门槛**（−10% + CI 排除 0 保持不变）。
- **不因本次裁决而删除 frame 0、删除折、或更换秩带 / 帧划分 / 结构阈值**（审计 §8）。

## 9. 指标可解释性：下一步该解决什么

本次审计把问题从"门槛没通过"转成了"门槛测的是不是我们以为的东西"。
要回答后者，最小的一步不是换门槛，而是给现有的 r 配一个**已知答案的合成基准**：
把同一份臂数据里的噪声按已知比例替换成独立噪声，看 r 是否随独立性单调、且在
"完全独立"时落到 Tetris 对照以下。这一步不涉及任何训练，也不需要新数据。

在这条曲线出来之前，任何"通过 / 不通过"的读法都缺少刻度。

## 10. 通俗总结

**这一步到底证明了什么。**

我们原来用的那把尺子，是拿"交叉拟合造出来的两条臂"去和"Tetris 造出来的两条臂"比，
看谁的两臂更不像。原来看起来差了 50%–111%，很糟。这一轮先确认了：**差得这么多，
主要是因为两把尺子量的是不同东西**——Tetris 把同一张图按体素相位劈成两半，
两条臂共用同一份噪声；交叉拟合的两条臂来自不同的帧，本来就是两份噪声。
这是"信息来源不同"，不是"处理手法不同"。

把这个差别拉平之后，交叉拟合在 SA64 上确实反超了，低 16%–19%，看着像通过了。

**但接着做了那个最关键的对照：把同一批帧随便打乱、随便切成两半，会怎样？**
答案是：**一样，甚至更好。** 16 折里只有 3 折真正比随机切分强，而那 3 折恰好是
"按时间连续切块"的——连续切块保住了帧与帧之间的时间相关性，占了便宜，
和 SVD 那套东西没关系。

**所以对项目主张意味着什么。**

原本想证明的是："从 C 组帧估出投影，套到 A、B 两组帧上，能得到一对噪声互相独立、
且都保住了图像内容的观测，可以拿去训练。"这一轮证明的是：
**现在这把尺子量不出这件事。** 它量到的是"两条臂来自不同的帧"——这件事对任何切法
都成立，等于什么也没说。而唯一能算数的那个对照（随机切帧）显示，交叉拟合没有
比别人多做出什么。

**哪些说法现在不能说。**

不能说"匹配之后门槛通过了，所以可以开始训练"。也不能反过来把它说成
"改完还是失败"——未匹配时那个难看的数字确实是混淆造成的，把它当结论同样是错的。

还有两件事不能再说：一不能说 frame 0 是个可以忽略的小瑕疵，它在自己那条臂里
占了总功率的 77%，是其余帧中位数的 288 倍，在 400 帧里排第一——它一直在悄悄
