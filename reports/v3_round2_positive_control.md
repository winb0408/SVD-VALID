## 0. 结论先说

在**本轮实际跑的这一档**（low，见 §2.3 为什么它其实比真实数据还容易）上，
自监督两臂（`A_rand`/`A_fixed4`）**没有通过** G-S0-1/2：`n2n_ratio` 2.22–6.73（> 1.0），
`r_roi` 0.981–0.995（输入 0.995–0.998），背景 std 比 0.98–1.03（几乎没去掉噪声）。
它们的输出比"什么都不做"更远离真值，也远差于一个**最优平稳线性滤波**（0.512）。
按审查 §7 的归因规则，这**不能**升级为"I1 被证伪"：判据本身没有退化
（zero 对照 848–902，输入 1.0，最优线性 0.512）。

**归因已经做到可以指名**（§5）：把目标从"互补相位视图"换成"同位置真值"（有监督上界臂）
**一分钱都没改善**（±0.8%，符号随种子翻转）；而在**训练几何**里网络确实把误差降到 0.53–0.55
（比恒等好 45%，训练体与留出体只差 0.013）；把训练几何改成**满分辨率**（与部署一致）后
`n2n` 从 2.17/2.76 降到 **1.17/1.56**（腰斩）。⇒ 失败与 I1 配对无关、与判据无关，
**最大的一块是训练/部署的空间几何不一致**——一个实现缺陷，按审查 §7 不能写成方法被证伪。

**但几何只解释了一部分**：满分辨率臂仍比"什么都不做"更差（`rmse/σ` 1.16–1.48 vs 恒等 1.00，
最优线性 0.17），且**自监督目标与真值目标在满分辨率下等价**（1.165 vs 1.171）。
§5.5 把剩下这部分钉死了：**噪声降到 1/3、问题明显更容易时结果更差**（`n2n` 4.97/7.57），
误差主体是一个与噪声大小无关的 ~0.02 常数项 ⇒ **这条训练链根本不在估计噪声**；
而训练体 12→60（五倍）只让 `n2n` 动 3%，**小于种子间差异** ⇒ 也不是数据量不够。
剩下的嫌疑只在**损失函数/网络结构/优化**，这一条**未修**，是下一轮的第一件事。

**唯一一条对项目主张有利的硬结果**：满分辨率几何下，"目标 = 另一次真实采集"与"目标 = 真值"
差 0.5%/1.2%（小于种子间差异）⇒ **自监督目标构造本身不损失信息**。这是项目主张需要的前提，
也是 I1 在本轮第三次被排除在嫌疑人之外。

## 1. S0 的设计（写在这里是为了让每个数字都能被复算）

| 项 | 设定 |
|---|---|
| 体尺寸 | (37, 64, 64)，与真实数据同形；`valid` 前 2 行置为无效（模仿近场死区） |
| 干净图 `gt_imaging_pd` | 3 个尺度档的软血管（半径 0.75/1.1/1.5，软边 1.0/1.5/2.0）+ 平滑本底，再按 PSF 平滑 |
| `gt_flow_pd` | 只含血流分量（**不是** S0 的主终点） |
| PSF | `SimCfg().psf_sigma = (3.0, 2.37, 3.97)`；PD 上等效核 = PSF 自相关 ⇒ `PSF_PD = PSF·√2` |
| 血流对比度 | 8 dB（血管 ROI 相对背景中位数） |
| 噪声 | PD 域**乘性**：`pd = clean · exp(σ z)`，z 为 iid 标准正态 ⇒ log 域**加性、信号无关**（正是 2026 SVD-SN2N 的核心物理前提） |
| 噪声档 | low σ=0.0385（v2 标定）、mid 0.077、high 0.154 |
| 两次观测 | `pd` 与 `pd2` 同一 clean、独立 z ⇒ 严格独立的两次观测（N2N 的目标定义） |
| `s` | 每卷 `s = median(pd[valid])`，输入表示 `log1p(pd/s)`（与 v2/VALID 同一接口） |

**自检**（造数据时打印，日志在 `reports/v3_round2/` 之外的 manifest 里）：
实测 log 域单次噪声 std = 0.0385 / 0.0771 / 0.1541，与目标逐档一致。

| **S0f** 评分正反标定（clean / identity / zero / blur / 过锐化 / 局部断血管 / 假血管） | **已执行 11 项**，其中 1 项是**定义问题**（`r_roi:fake`） | §2.1 |

**§1.2 为什么 S0c 没跑**：审查 §8 的决策表自己写了"**S0 简单独立噪声都失败 ⇒ 更可能是实现、
训练目标或评价链未正确建立，首先修正 fidelity；暂停大规模 C**"。S0c 是**在 S0a 通过之后**
才有解释力的下一级（它问的是"相关性升高时去噪效果怎么变"）。当前 S0a 未通过且归因指向实现，
此时叠加相关性会把"几何/推理缺陷"和"相关性效应"混在一起，两个都读不出来。所以按决策表的顺序冻结。

**§1.3 S0d 已知的对不齐方向**（必须写明，否则"正控制"这个名字会被读大）：
① S0 的血管是解析管状 phantom，**没有真实数据的静态散斑与低秩杂波**，所以 S0 的"背景"比真实干净；
② 真实数据的噪声在 log 域近白（相关长度 0.63–1.34 体素），而 S0 的噪声是**严格独立**的——
方向上是"S0 比真实更白"，与 v2 仿真（比真实更平滑）**方向相反**；
③ S0 的噪声幅度只匹配了 log1p 域的标准差，没有匹配 `Var(noise|signal bin)` 的形状（真实数据是乘性 ⇒
线性域方差 ∝ 信号²，S0 在 PD 域也是乘性、log 域是加性，这一条**是对齐的**）。
结论：S0 是"最简单可信的任务"，它通过不了**不能**反推真实数据上的难度，只是排除了"连最简单任务都做不了"。

## 2. 端点与判据

主终点两个，写在 `reviews/V3_PR1_round2_plan.md` §3.2：

- `n2n_ratio = mse(pred, obs2) / mse(obs1, obs2)`：< 1 才算"比输入更接近第二次观测"；
- `r_roi = corr(pred, gt_imaging_pd)` 在 ρ>0 内：必须高于输入的同一读数。

辅：`r_flow`（参考量）、`bg_std_ratio`、`rmse_vs_imaging`。

G-S0-1 两臂所有格子 `n2n < 1.0`；G-S0-2 两臂所有格子 `r_roi > 输入`；
G-S0-3 评分正反标定（除已记录的 `r_roi:fake` 端点定义问题外全部顺序成立）。

### 2.1 评分标定（S0f，跑在任何训练之前）

`scripts/v3_round2_s0_calibration.py` 用**已知损坏**做正反标定，11 项检查：

| 端点 | 检查 | 结果 |
|---|---|---|
| `n2n_ratio` | clean > input | 通过 |
| | input > zero / blur / sharp / broken / fake | 全部通过 |
| `r_roi` | clean > input / input > blur / input > broken | 通过 |
| | **input > fake** | **未通过（定义问题，见下）** |
| `r_all`（补） | input > fake | 通过 |

`r_roi: fake` 未通过的原因是**端点定义**而不是判据坏了：`fake` 把一根人造血管注入到 ρ=0 的
背景里，而 `r_roi` 的掩膜是 ρ>0，被注入的血管落在掩膜外，所以 `r_roi` 看不见它。
记录在档，**没有改门槛**，另补一条 `r_all` 检查来覆盖这个方向（通过）。

### 2.2 上界与参照（全部无训练、可直接复算）

| 对照 | n2n（e900 / e901） | r_roi |
|---|---|---|
| input（什么都不做） | 1.000 / 1.000 | 0.9947 / 0.9978 |
| zero | 848.6 / 902.5 | nan |
| oracle_truth（把真值当预测） | **0.501 / 0.503** | 1.0000 |
| oracle_freq_wiener（最优平稳线性滤波） | **0.512 / 0.515** | 0.9999 |
| wiener_w7（7 体素窗） | 3.350 / 3.852 | 0.9924 / 0.9961 |
| oracle_lowpass（按 `PSF_PD` 平滑） | 38.34 / 43.62 | 0.8507 / 0.9377 |

这张表是本次最重要的一张，它说明三件事：

1. **任务有空间**：`oracle_freq_wiener` 把 n2n 从 1.0 压到 0.51（几乎等于理论下限 0.50）。
   所以"数据里没有可去噪声"这个解释不成立。
2. **但只能轻轻去**：7 体素窗的 Wiener 就已经从 1.0 升到 3.35，按 `PSF_PD`（σ≈3.4–5.6）
   平滑更是升到 38–44。量一下结构对平滑的敏感度：对真值做 σ=1 的高斯平滑，
   RMSE 就达到 0.0150，而噪声本身只有 0.020（log1p 域）——**平滑立刻吃掉全部收益**；
   σ=2 时 RMSE 0.0492，σ=3 时 0.0920。
3. 因此"重度平滑"类对照的低分是**结构偏差**造成的，不是评分器坏了。

### 2.3 噪声档与真实数据的对齐（S0 的一个自我更正）

标称 σ 是 **PD 域乘性**的幅度，而网络看到的输入是 `log1p(pd/s)`，log1p 在 `pd/s≈1` 处把噪声
压缩约一半。所以"标称 σ=0.0385"在模型输入上是 **0.0198**，不是 0.0385。
真实数据走同一个 log1p，所以必须在**同一表示里**比（`scripts/v3_round2_s0_level_match.py`）：

| | log1p 域 σ_eff |
|---|---|
| 真实 SA64（一次全长观测） | 0.0272 |
| 真实 HSA64（一次全长观测） | 0.0399 |
| S0 low | **0.0198**（压缩 0.51×） |
| S0 mid | **0.0397** |
| S0 high | **0.0795** |

**结论：low 档比真实数据还容易（约 0.7× / 0.5×），mid 档才是真实数据那档**（与 HSA64 几乎相同，
比 SA64 高 1.5×）。这一条是"先跑 low 就够了吗"的答案：不够，主结论必须在 mid 上复验。

### 2.4 这份数据的一个限制（必须写明）

S0 的"背景（ρ=0）"里有一层**平滑本底**，其 log1p 域标准差 0.367，远大于噪声（0.020–0.040）。
所以 `bg_std_ratio` 在这里**不是噪声指标**（它几乎全被本底结构占据），只能当"有没有把结构抹掉"
的粗看。v2 数据里背景是散斑主导，同一指标才是噪声指标。这一点会误导读者，故显式声明。

**fail 机制（可量化）**：模型输出相对输入的偏离 `mse(pred, obs1)` = 1.71e-3 ~ 3.91e-3，
而噪声本身只有 3.9e-4（mse(obs1,obs2)/2）。比值 4.4–10 倍 ⇒ 网络不是"没学到去噪"，
而是**在噪声之上又加了一份更大的误差**（≈1.5–2.5σ）。affine 拟合 `truth ≈ a·pred + b` 给出
a = 0.965–0.978、b = +0.008~+0.040，输出整体略被压暗并抬底。

当时的推测是"欠训练 + 小波 Hessian 正则把低频抹平"。**§5.2 已经把这个推测否掉了**：
同一个 checkpoint 在训练几何里把误差降到 0.53–0.55（比恒等好 45%），且训练体与留出体一致
⇒ 既不是欠训练也不是没学到，是**部署时换了它没学过的几何**。这一段的数值保留不改，
免得看起来像"后来把不利读数改掉了"。

## 4. 与旧判定的关系

- 旧 T1/T2 判定（`reports/v3_expA_v2/gate_verdict.json`）**原样保留**：v2 仿真上 200k step 也从没
  过门（n2n 1.74–12.4，r_roi 0.18–0.78 < 输入 0.80–0.82）。
- 本轮 S0 是同一种失败形态的**独立复现**，但 S0 是"数据本身干净、噪声已知、任务已知可行"的设定，
  所以它比 v2 更有利于定位问题：数据没问题（oracle_freq_wiener 0.512），失败在训练/目标/推理链。
- 两者**互不蕴含**：S0 不通过**不**说明 I1 错；v2 不通过也**不**说明真实数据上不行。

## 5. 归因：失败**不是** I1 配对造成的，而是训练几何与部署几何不一致

审查 §7 要求「失败必须给机制，不能只说没通过」。S0 的失败可以拆成四个互斥的候选原因，
下面每一条都用一次**只改一个变量**的实验去否掉，写在跑之前。

**符号随种子翻转**（3407 上监督略好、3408 上略差），量级小于种子间差异本身（同臂两 seed 差 2–19%）。
所以这是种子噪声，不是系统性差异。**把"目标换成真值"完全救不回来** ⇒ 失败与 I1 配对无关。
这也顺带说明：S0 是"连有监督也过不了"的情形，不是"自监督特有"的失效。

### 5.2 候选②「网络根本没学到东西（欠训练/容量不足）」→ **否掉**

在**训练几何**里问一个和 `n2n_ratio` 同构的问题：给定输入视图 `x_a`，网络预测配对视图 `y_a`，
能不能比 `x_a` 本身更接近 `y_a`？

```bash
python -u scripts/v3_round2_s0_train_geometry.py --level low --runs runs/v3_round2_s0/low \
    --arms A_rand S_rand --seeds 3407 3408
```

| 臂 | 种子 | 训练体 ratio | 留出体 ratio |
|---|---|---|---|
| A_rand | 3407 | 0.536 | 0.548 |
| A_rand | 3408 | 0.532 | 0.545 |
| S_rand | 3407 | 0.536 | 0.548 |
| S_rand | 3408 | 0.532 | 0.547 |

（<1 = 在该几何里优于恒等。`reports/v3_round2/s0_train_geometry.json`）

三件事一起成立：①网络在该几何里把误差降到 **0.53–0.55**（比恒等好 45%）⇒ **学到了**；
②训练体 0.532–0.536 vs 留出体 0.545–0.548，差 0.013 ⇒ **没有过拟合**；
③自监督与有监督**逐位相同**（0.548 vs 0.548）⇒ I1 配对在训练几何里**一分钱都没多花**。
于是"没学到"和"配对有毒"两条被同一次测量否掉。

### 5.3 候选③「推理时的相位重装配能救回来」→ **否掉**（三种推理口径全测了）

`infer.py` 在满分辨率 patch 上推理，而训练时网络看到的是**半尺寸相位视图**——注意这不是"尺寸不匹配"
（网络是全卷积的，尺寸随便），而是**采样密度不一致**：训练输入的相邻体素在原体上隔了 2 个体素，
推理输入的相邻体素是相邻的。同一个卷积核因此被用在"频率"高了一倍的内容上。
这是本轮发现的一个实现层不一致。自然的修法是把推理也改成相位一致，所以直接测了三种口径
（同一 checkpoint、同一评价函数，只差"输入怎么来、输出怎么拼"）：

| 口径 | 做法 | A_rand s3407 (e900/e901) n2n | A_rand s3408 |
|---|---|---|---|
| **A 满分辨率（现状，= `infer.py`）** | 整卷直接过网络 | 2.274 / 2.216 | 2.793 / 1.873 |
| B 相位一致 | 8 相位各自抽稀→网络→**按相位原位**贴回 | 7.108 / 6.677 | 4.195 / 3.570 |
| C 相位平均 | 8 相位各自过网络→**平均后重复升采样** | 9.277 / 10.625 | 6.427 / 6.982 |

16 个格子（4 臂 × 2 种子 × 2 评估体）**无一例外** B、C 都比 A 更差，C 最差。
`S_rand`/`S_fixed4` 两臂同样的顺序（见 `reports/v3_round2/s0_phase_infer.json` 全表）。
⇒ "把推理改成相位一致"这个修法**被实测否掉**，它不是解药。

### 5.4 候选④「训练几何本身与部署几何不一致」→ **证实是最大的一块，但不是全部**

把训练**改成满分辨率**（`--mode dense`，目标仍是同位置无噪 patch），部署口径完全不变。
这是唯一能让训练几何与 `infer.py` 对齐、同时不改变任何评价设置的实验：

```bash
bash runs/v3_round2_s0/launch_dense.sh low 0 40 500      # S_dense × 2 种子
python -u scripts/v3_round2_s0_eval.py --level low --runs runs/v3_round2_s0/low \
    --arms S_dense D_n2n --out reports/v3_round2/s0_low_metrics_dense.json
```

**结果（两个种子都跑完，`history.json` 齐；`n2n` 与"偏离真值多少倍噪声"并列）**

`rmse/σ` = `rmse_vs_imaging / σ_eff`，σ_eff = 0.0198。**恒等（什么都不做）就是 1.00**，
所以 > 1 意味着"比不做还差"，< 1 才是真去噪；最优平稳线性滤波（oracle）是 0.17。

| 口径 | 目标来自 | e900 `n2n` / `rmse/σ` | e901 `n2n` / `rmse/σ` |
|---|---|---|---|
| 输入（恒等） | — | 1.000 / **1.00** | 1.000 / **1.02** |
| 相位几何 `A_rand` s3407 | 互补相位视图 | 2.217 / 1.85 | 2.717 / 2.14 |
| 相位几何 `S_rand` s3407 | **真值** | 2.166 / — | 2.763 / — |
| **满分辨率 `S_dense` s3407** | **真值** | **1.171** / 1.16 | **1.559** / 1.48 |
| **满分辨率 `S_dense` s3408** | **真值** | **1.233** / 1.22 | **1.533** / 1.47 |
| **满分辨率 `D_n2n` s3407** | **第二次观测**（自监督） | **1.165** / 1.16 | **1.541** / 1.47 |
| （参照）oracle_freq_wiener | — | 0.512 / 0.17 | 0.515 / 0.18 |

**三条结论**（上表全部格子 + 本文其余各臂画成一张图见 §5.7 图 1）：

1. **几何是最大的一块**：只把训练改成满分辨率，`n2n` 从 2.17/2.76 降到 1.17/1.56（降 46%/43%），
   两个种子一致（1.171 与 1.233）。按跑之前写好的判读规则，这落在"**仍不过，但明显优于 S_rand**"这一格。
2. **自监督配对在满分辨率几何下与真值目标等价**：`D_n2n`（目标 = 另一次真实采集）1.165/1.541
   vs `S_dense`（目标 = 真值）1.171/1.559，**差 0.5%/1.2%，小于种子间差异**。
   这是本轮唯一一条对项目主张**有利**的硬结果：**"用你手里的另一次观测当目标"这件事本身不损失信息**，
   前提是几何对得上。它把"I1 配对有毒"这个假说再否一次，而且是在更好的几何里否的。
3. **但两个满分辨率臂都仍然比"什么都不做"更差**（`rmse/σ` 1.16–1.48 vs 恒等 1.00），
   与最优线性滤波（0.17）差 7–9 倍。**所以剩下的缺口不能再用目标或几何解释**，
   只能是"这条训练链在该容量/预算/损失下根本没有学出去噪算子"。候选⑤（已知答案标定，§5.5）
   就是为这一条准备的。

**一条必须纠正的自我误读**（画成图是 §5.7 图 3）：训练损失 `S_dense` 在 epoch 16 就到 4.2e-4，我一开始把它读成"拟合得很好"。
`σ² = 3.9e-4`——**损失等于噪声方差，恰恰说明它基本没去噪**（恒等解的损失就是 σ²）。上表的
`rmse/σ = 1.16` 才是正确读法（比恒等差）。这条保留在这里，因为它正是"训练损失不能当验收标准"的
第 N 次复现。

### 5.5 候选⑤「这条训练链能不能去噪任何东西」→ 已知答案标定（`vlow` 档）

§5.4 把几何与目标都排掉之后，剩下的嫌疑是训练本身（容量/预算/损失）。在动超参之前，先做一个
**已知答案**的检验（方案 §0.5 的纪律：任何新判据/新流程都要先在一个答案已知的问题上标定）：

把噪声降 3 倍（`vlow`：标称 σ 0.0128，输入上 σ_eff ≈ **0.0066**，是 low 档的 1/3），
其它一切不变（同样的 12 卷、同样的 dense 几何、同样的 40×500 预算）。在这个档上，
**一个正确的去噪器应该轻松拿到 `n2n ≈ 0.55–0.7`、`rmse/σ < 0.7`**（因为噪声小、信号结构更容易学）。

`vlow` **不是**审查要求的 low/mid/high 阶梯的一档（已在 `scripts/v3_round2_s0_dataset.py` 里注明），
它只服务这一个问题。判读规则写在跑之前：

| `vlow` 的结果 | 含义 |
|---|---|
| `n2n` 明显 < 1（如 ≤ 0.8） | 训练链**能**去噪；low/mid 的失败是"该容量/预算在低信噪比下不够"——可按预注册加容量/预算，属实现修正 |
| `n2n` 仍 ≥ 1 | 训练链**在显然可做的问题上也不工作** ⇒ 问题在损失/优化/架构本身，与信噪比无关；下一步必须先修这条链，任何采样先验实验都无意义 |

**结果（`S_dense` s3407，40×500 跑完，`history.json` 齐，22:13 回填）**

```bash
python -u scripts/v3_round2_s0_eval.py --level vlow --arms S_dense --seeds 3407 \
    --out reports/v3_round2/s0_vlow_metrics.json
```

| 口径 | e900 `n2n` / `rmse/σ` | e901 `n2n` / `rmse/σ` |
|---|---|---|
| 输入（恒等） | 1.000 / **1.00** | 1.000 / **1.00** |
| `S_dense` s3407（`vlow`） | **4.970 / 3.00** | **7.570 / 3.84** |
| （参照）oracle_freq_wiener | 0.517 / 0.17 | 0.521 / 0.18 |
| （对照）zero | 7633 / — | 8114 / — |

**判读（按跑之前写好的两支）**：落在第二支——**训练链在显然可做的问题上也不工作**。
在这个档上正确实现本该轻松拿到 `n2n ≈ 0.55–0.7`，实测是 **4.97/7.57**，比 low 档的 1.17/1.56 **更差**。
而且这不是"降噪变弱"，是**相对破坏变大**：

| | low（σ_eff 0.0198） | vlow（σ_eff 0.0066） | 比值 |
|---|---|---|---|
| `rmse_vs_imaging` e900 / e901 | 0.02304 / 0.02939 | 0.01979 / 0.02532 | 0.86 / 0.86 |
| `rmse/σ` e900 / e901 | 1.16 / 1.48 | **3.00 / 3.84** | 2.6× |
| 训练末损失 / σ² | 0.16 | 1.15 | — |

噪声降了 3 倍，网络输出的**绝对误差几乎没变**（只降到 0.86 倍，而不是 0.33 倍）。
把 `rmse(pred, truth)`（y）对 `rmse(input, truth)`（x）在 4 个格子（2 档 × 2 体积，
`reports/v3_round2/s0_{low_metrics_dense,vlow_metrics}.json` 的 `input` 与 `S_dense_s3407`）上回归：
**`a = 0.283`、`b = +0.0206`，残差 ±0.003，R² = 0.29**（这四个点连同拟合线、恒等线、
"完美去噪器应落在哪"的带子画成 §5.7 图 2）——斜率近乎为零，也就是
**预测误差的主体是一个 ~0.02 的常数项，与输入噪声大小基本无关**。这才是这条链的真实行为——
它不是"去噪去得不够好"，而是**根本没有在估计噪声**，输出的偏差是训练分布上的常数项
（12 卷训练体上拟合出来的成分），换一个噪声档就原样保留下来。

同时训练损失给出了独立的、方向相同的一击：low 档训练损失降到 `0.11–0.16 σ²`（训练几何里确实降了 6 倍，
与 §5.2 的 0.53 一致），但**留出体上的误差比"什么都不做"还大**；`vlow` 档训练损失 `1.15 σ²`
**一点没降**（恒等解的下界就是 1.0）。训练集能压下去、留出体压不下去，说明压的是**这 12 卷本身**。

**所以候选⑤的答案是否定的，而且它把下一步指向了两个具体的、可检验的东西**（不是"调超参"这种空话）：

1. **训练体数量**：12 卷 × 500 步 × 40 轮 = 2 万次采样，全部来自同一批解剖；留出体上的常数偏差正合"记住了训练解剖"。
   直接检验：`low60`（同分布、60 卷训练体、其余完全不变，`launch` 见 §6）——若 `n2n` 随数据量显著下降，
   约束是数据量；若不动，约束在损失/架构/优化，与数据无关。
2. **目标函数形式**：现有损失是 `mse(pred, target)` 上的一项。若网络学到的是"把输入整体拉向训练集均值"，
   需要的是对"偏离输入的成分"做惩罚/门控，而不是整体 L2。但这一条**在①的结论出来之前不动手**——
   方案 §0.5 的纪律是"不换配置救火"，先知道是数据不够还是链坏了。

**①的直接检验结果：`low60`（23:24 跑完，`S_dense` s3407）**

先固定可比性，避免"换了别的东西"的指控：

| 项 | `low`（原 12 卷） | `low60`（诊断） | 是否变 |
|---|---|---|---|
| 评测体 npz | `s0_low_e900/e901` | **同两个文件，SHA256 前缀 `13e44524…`/`a873ce2e…` 逐字节相同** | **不变** |
| 训练体种子 | 200–211 | 200–211 **+ 新增 212–259**（前 12 卷逐位相同，严格超集） | 只加不减 |
| σ / 噪声域 / PSF / patch / 预算 / 种子 / 损失 | low, log 域加性, 同一 PSF | 同 | 全部不变 |
| 唯一变量 | — | **训练体数量 12 → 60** | **仅此一项** |

| 指标 | 12 卷训练体 | 60 卷训练体 | 变化 |
|---|---|---|---|
| `n2n` e900 | 1.171 | **1.137** | −2.9% |
| `n2n` e901 | 1.559 | **1.507** | −3.3% |
| `rmse/σ` e900 / e901 | 1.16 / 1.48 | 1.13 / 1.45 | −2.5% / −2.0% |
| `r_roi` e900 / e901 | 0.9947 / 0.9962 | 0.9961 / 0.9968 | +0.0014 / +0.0006 |
| 训练末损失 / σ² | 0.16 | **0.16** | 不变 |

**判读**：训练体加 5 倍，`n2n` 只动 3%；同期**种子间**差异是 1.7%（e901）到 5.3%（e900）——
**数据量的效应落在种子噪声里**。而要有意义，`n2n` 得从 1.5 掉到 1 以下（−34%）、掉到最优线性滤波那样（−66%）：
**5 倍数据买到 3%，差一个数量级以上**。训练末损失也原样停在 `0.16 σ²`，加数据**没有改变拟合的水平**。

⇒ **候选「数据量不够」否掉**，落在跑之前写好的第二支：**问题在损失函数/网络结构/优化**。
这一条同时说明，§5.5 开头"训练集压得下去、留出体压不下去"**不是**普通过拟合——真过拟合的话 5 倍数据应显著缓解它，但没有。
（未执行：只跑 s3407 一个种子——效应量 3% 已小于种子间差异，补种子不改方向；若要写进正式结论需补 2–3 个种子给区间。）

> **一节说明为什么这一条比 §5.4 更重要**：§5.4 只是说"几何不对会掉分"，§5.5 说的是"**这条链在噪声更小、
> 更容易的问题上表现更差**"。任何"再多训一会儿/再加点采样先验/B 和 C 阵容"的方案，在这条结论面前都不成立——
> 它们都建立在一个还没验证的假设上：网络至少在朝"去噪"的方向走。现在没有证据表明它在走。

**未执行**：`vlow` 只跑了一个种子（这个判据的效应量 4.97 vs 0.55 远大于种子间差异 1.17 vs 1.23，
一个种子足够定性；若要写进正式结论需补 s3408）。

### 5.6 目前能下的结论与不能下的结论

**能说**：
1. S0 在本轮跑的 low 档上**未通过**（这是实测，不是推断）；
2. 失败**不是** I1 配对造成的（§5.1 监督与自监督逐位相同）；
3. 失败**不是**欠训练/过拟合/没学到造成的（§5.2 训练几何里 45% 的改进、留出体一致）；
4. 失败**不是**判据坏掉造成的（§2.1 标定 10/11，zero 对照 848–902，最优线性 0.512）；
5. 训练与部署的**空间几何**不一致，且这个不一致**不能**靠"推理端补相位"修好（§5.3）；
6. 几何修好之后 `n2n` 降 43–46% 但**仍未过门**，剩下的缺口不能再用目标/几何/判据解释（§5.4）；
7. **自监督目标不损失信息**：满分辨率几何下"目标 = 另一次真实采集"与"目标 = 真值"差 0.5%/1.2%（§5.4）；
8. 这条训练链**在显然可做的问题上表现更差**（`vlow`：`n2n` 4.97/7.57，误差主体是与噪声无关的常数项）（§5.5）；
9. **数据量不是主要约束**：训练体 12→60，`n2n` 只动 3%，小于种子间差异（§5.5）。

**不能说**：
1. "I1 在超声上不成立"——S0 的失败在监督臂上同样出现，与本项目的核心主张无关；
2. "方法不行"——本轮只否掉了实现链，没有触及方法；
3. "S0 通过"——没有；也不能把 low 档的结果外推到 mid 档（§2.3 已证 mid 才是真实数据那档）；
4. "再多加些数据就能过门"——已被 §5.5 的 12→60 检验直接否掉（3% vs 需要的 34%+）；
5. "采样先验（I1）现在可以做实验验证了"——不行。链子还没修到能在已知答案上拿到正常分数，
   此时任何采样先验的差异都读不出来。**顺序是：先修链，再谈采样。**

**这一条"先修链"已经写成单独方案**：[`reviews/V3_PR1_round2_next_plan.md`](../reviews/V3_PR1_round2_next_plan.md)
（Round3 预注册：A 段四项只读诊断 + B 段四条单变量修复，门槛全部写在跑之前，**尚未执行**）。
本文件**不新增结论**，只把 §5.5 的"误差不随噪声缩放"这条实测事实作为它的出发点。

## 8. 通俗总结

**这一步到底做了什么。** 上一轮外部审查说了两件事：一，不要再用模拟数据争论，先去看真实数据里到底还剩不剩噪声；
二，既然说"自监督配对能用"，那就造一个噪声是我们自己加的、正确答案已知的数据集，看方法能不能把它去干净。
这份报告做的是第二件事的第一站（编号 S0）。我们造了四档"加了已知噪声"的三维数据（三个递增的噪声档，
外加一个"噪声只有最容易档三分之一"的档；其中最难的那一档只造了数据、没上训练），
用完全相同的训练预算（4 种配置 × 2 个随机种子，每档 40 轮 × 500 步）去训，
再用一套**在训练开始之前就写死**的评分规则去判。评分规则本身先在一个答案已知的玩具问题上验过：
该给高分的给高分、该给低分的给低分，没有坏掉。

**结果是什么。** 没过。两档都过不了：容易的那一档（low）八个训练配置全部比"什么都不做"更差，
差的幅度从两成到七倍不等；和真实数据同样难的那一档（mid）好一些，个别配置在个别体积上开始比"什么都不做"略好，
但仍没有一个配置整体过关。

**为什么没过——这是本报告真正的产出。** 发现没过之后，我们挨个排查了可能的责任人，每一步都只改一个变量：

- 是不是"用另一次采集当训练目标"这个做法本身有毒？不是。把目标换成真值，结果和原来**几乎一模一样**
  （mid 档几乎逐位相同）。这条路被排除了。
- 是不是网络根本没学会、欠训练？也不是。在它自己训练用的那种视角下，它确实把误差压掉了一半；
  问题出在这个能力没带到实际使用时的视角上。
- 是不是推理时补一补就能救回来？不是。我们把三种推理方式全部试过，另外两种都更差，十六个格子里没有一次更好。
- 是不是训练时"看东西的方式"和实际使用时不一致？**对，这是最大的一块。** 只把训练改成和使用时相同的视角，
  误差立刻降了四成多（两个种子一致）。这是本轮唯一一个"改动正确、幅度明显"的发现。
- 剩下那部分缺口，是不是因为噪声太小/太大？**恰恰相反**：把噪声降到原来的三分之一、把问题变得明显更容易之后，
  结果**更差**了。噪声小了，它输出的偏差几乎没变——说明它不是"降噪降得不够好"，而是**根本不在估计噪声**，
  它学到的是训练数据本身的一个固定偏置，换个噪声档就原样搬过去。

**对项目主张意味着什么。** 三句话：

1. **这一轮完全没有碰到项目的方法主张。** 项目想证明的是"用手里已有的两次观测互相监督，能把采样不足补回来"。
   而上面所有失败，在"用真值当目标"的对照组里**一模一样地重演**——那是任何教科书式做法都会用的配置。
   换句话说，坏掉的是"我们这条训练-推理流水线"，不是"I1 配对"这个想法。
   反过来说，本轮唯一一条**对项目有利**的硬结果也在这里：在视角对得上的前提下，
   用"另一次真实采集"当目标和"用真值"当目标，结果差了不到一个百分点——
   **自监督这件事本身不损失信息**。这正好是项目主张需要的前提。
2. **现在还不能说"方法不行"，也不能说"方法行"。** 前者是因为坏的是实现，后者是因为我们还没让实现工作过。
3. **旧结论一律不变。** 之前对 T2 的否决（采样先验在真实数据上无效）没有被这个实验翻案，
   这个实验也没有被那个否决牵连——两件事互不蕴含，这一点在进度文档里也写明了。

**现在不能说、容易被误读的几句话（列在这里就是防止有人引用错）：**

- "I1 在超声上被证伪了"——错。I1 在这轮里被**三次**排除在嫌疑人之外（换目标不变、mid 档重演、满分辨率下与真值等价）。
- "真实数据里没有可恢复的噪声，所以项目前提不成立"——错，而且方向相反。真实数据的审计（另一份报告）
  明确显示还剩相当量的噪声、而且空间上接近白噪声，正是可以处理的那一类。
- "训练损失很小，说明训练成功"——错，本轮实际踩到了这个坑。损失降到噪声方差以下看起来像好事，
  但留出数据上的误差比不做还大。这个数不能当验收标准，只能用留出数据的评分。
- "再多训一会儿 / 再多喂点数据就好了"——两条都被实验否掉了：噪声更小、更容易的任务上表现更差
  （不是训练不足），五倍训练数据只换来 3%（不是数据不够）。

**最后做的一个"只改一个变量"的检验，结果也出来了。** 我们怀疑过"是不是给它看的样本太少，它在背训练集"。
于是把训练用的体积从十二个加到六十个（五倍），其余——噪声、组织、评分规则、训练预算、随机种子——一个都没动，
评测用的还是原来那两个文件（逐字节相同）。**结果只好了百分之三**；而同一个配置换个随机种子，结果就能差百分之二到五。
也就是说：**五倍数据买来的改进小到和运气分不开，而它需要的是改进百分之三十以上。**
这条把"再加点数据就好了"这个最自然的辩解直接排除了。

**所以下一步不是"再调一调"，而是要动真正坏掉的地方。** 现在的证据把问题指向损失函数、网络结构、优化这三样；
数据、训练目标、训练几何、评分尺子这四样，要么已经修好，要么已经独立排除。
具体动哪一样，要在**下一次审查之前写一份单独方案**，先写清"改什么、为什么、预期看到什么数"，再动手。
本轮到此为止，不在这里凭感觉试配置——因为一旦改了又同时改了别的东西，就没人能说清是方法有效还是配置撞对了。

**还有一句必须留给下次审查的话**：这一轮把"是哪里坏了"钉到了很具体的程度，但**没有**证明"改对了就能过门"。
目前的全部证据只支持一个判断：**在现有这条训练链上，采样先验实验没有意义**——因为连"把已知的噪声减掉"都做不到。
等链子修到能在一个显然可做的问题上拿到正常分数，再谈采样、再谈真实数据。顺序不能反。
