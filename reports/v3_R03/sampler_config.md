## 1. 为什么要冻结：采样器的行为由六类外部输入决定，其中四类在磁盘上

| # | 输入 | 落在哪里 | 变了会怎样 |
|---|---|---|---|
| 1 | 几何：m=2、w=3、8 个 tet 角点表、互补表 | `datasets/sampling.py` | m 变了位移类的物理尺寸就变，角色序**不能外推**（`v3_phase2_role_order.md` §6） |
| 2 | 物理先验 ρ（实测散斑自相关，去平台快速分量） | `data/processed/v3_correlation_length.json` | 换数据/重算 = 换了一个先验，日志里看不出来 |
| 3 | 角色序（由 ρ 推出的有序角色对泄漏 L 排序） | `data/processed/v3_role_order_m2.json` | 挑角色的方法就变了 |
| 4 | 频带：官方 1-based `M(:,60:350)` = 291 模式 = 0-based `[59,350)` | `v3_phase5_real_compare.py::band_slice` | R13 已抓到过"少一个模式" |
| 5 | 成像常数：PSF σ=(3.0,2.37,3.97)、热噪声 σ=(1.0,1.2,1.1) | `v3_simulator.py::SimCfg` | `oracle_lowpass` 对照用的是同一个核，改了对照就偷步 |
| 6 | 有效区掩膜 | `official/{SA64,HSA64}/valid_mask.npy`（真实） / `valid[:2]=False`（仿真） | 指标口径变化 |

`scripts/v3_sampler_config.py --build` 把六类连同 **sha1** 写进 `configs/sampler_config.json`；
`--check` 重新计算并逐项比对，不一致退出码 1。

## 2. 端到端接入点：`train.py --sampler-config`

```bash
python train.py ... --sampler-config configs/sampler_config.json
```

行为：①先跑 `v3_sampler_config.py --check`，不过就 **`SystemExit(2)`，不写半截 checkpoint**；
②只接受仓库内那一份配置（校验脚本与它绑定，防止拿一份改过的副本绕过）；③通过则把副本与
`sampler_config.sha1` 落进 `--out` 目录。这样任何一个 run 都能回答"它用的是哪份先验/哪个秩带/哪条角色序"。

冒烟验证（CPU，1 epoch × 2 step）：

```
[R03] sampler_config OK  sha1=4b486475878f  -> /tmp/r03_smoke/sampler_config.json
epoch=001 loss=17.885356 lr=0.00e+00
```

## 4. 没做的那一半：错误先验的负控制（属实验 C，门未通过）

`negative_controls` 里写好了 4 条臂的规格，状态 `spec_only_not_run`：

| 臂 | 怎么做 | 隔离出什么 |
|---|---|---|
| `wrong_role_swap` | 同样 4 个体素、同样的输入，只把两个目标对调：正确 `[1,4,6,3]` → 错误 `[1,4,3,6]` | **角色/位移**，覆盖率与坐标完全不变 |
| `wrong_prior_isotropic` | 实测 ρ → 各向同性 `exp(−|δ|/ℓ)` | 先验的**各向异性**部分 |
| `wrong_prior_axis_permuted` | ρ 的轴长循环错位 (z,y,x)→(y,x,z) | 轴序错误会不会把采样器带偏 |
| `strongest_fixed_pattern` | 固定用泄漏最小的 tet，不随机抽 | 随机化本身是否必要 |

为什么不跑：`reports/v3_expA_v2/prereg.md` §3.3 已经把"实验 A 的门不通过则 B/C/D 冻结"写死。
门的结果**在写这份文件时还不知道**（阶段 2 训练 01:22 时跑到 66/200）。先跑负控制再补门槛
就等于事后调门槛，方案 §0.5 明文禁止。

## 5. 顺带核出的一件事：仿真有效区 ≠ 官方有效区

R13 的"valid_mask 审计"此前只对比了两份官方掩膜**彼此**相同，没对比仿真与官方。这次补上：

| 掩膜 | 覆盖 | 形状 |
|---|---|---|
| 官方 SA64（= HSA64） | **0.820** | z=0,1,2 全无效；z=3..13 逐层渐开（扇形成像足迹） |
| 仿真 `valid[:2]=False` | **0.919** | 只挖掉近场死区 |
| 两者 IoU | **0.867** | 覆盖差 +0.126 |

后果写进了配置的 `disclaimer`：**"仿真指标可迁移到真实数据"这句话在有效区口径上也不成立**；
仿真内部各臂之间可比，跨仿真/真实的绝对值不可比。这一条不新，但此前没有被量化记录。

## 6. 通俗总结

**这一步到底证明了什么。** 我们的采样方法不是一段代码，而是一整套"外部输入"：实测的噪声相关性、
由它算出的角色排序、管用哪个秩带、成像镜头的模糊程度、以及哪里算有效像素。这些以前只写在文档和注释里——
换个数据文件、重算一次相关性，方法其实已经变了，但训练日志看上去一模一样。现在这些输入连同各自的
指纹（校验和）被写进一份配置文件，训练**启动前**会核对，对不上就拒绝开始，并且把这份配置复制到
本次训练的目录里。等于给每次实验发了一张"配方卡"，事后能查清它到底用了什么。

**对项目主张意味着什么。** 这一步不产生任何新结论，它保护的是**后面所有结论**：实验 C 要比较
"用对的物理先验"和"用错的物理先验"，如果连"对的先验是哪一份"都说不清，那个比较就没有意义。
另外顺手量到了一个此前只是嘴上说说的差异：仿真里的"有效像素"比真实数据多出约一成，
所以仿真的绝对分数不能直接搬到真实数据上说事。

**哪些话现在不能说。** 不能说"物理先验已经端到端跑通了"——配置冻结与校验做了，但**用错先验会
不会变差**这件事一次都没跑（属实验 C，门未过）。不能说"仿真和真实数据在有效区上一致"（IoU 0.867）。
也不能说"重训新实验一定用了这份配置"——阶段 1/阶段 2 的那 8 个 run 是**加这个参数之前**启动的，
它们没有配方卡，这是本轮已知的缺口，只有在下一批 run 里才会带上。

**剩余风险**：① 校验只覆盖"输入有没有被换"，不覆盖"代码有没有被改"——`v3_role_order.py` 的算法
若被改而输出 hash 恰好不变（概率极低但非零），校验看不出来；② 负控制 4 条臂目前只有文字规格，
实现时若把"错误先验"实现得过于离谱，会得到一个没有信息量的负结果，这一步必须在跑之前先把
"错误先验的离谱程度"写成可核对的量；③ 有效区差异 0.126 尚未反映到任何已有指标里（历史数字未改判）。
